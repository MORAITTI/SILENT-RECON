# SILENT-RECON

**Панель наблюдения за HTTP-запросами и событиями сетевого сенсора Suricata.**

SILENT-RECON объединяет события встроенного HTTP-сервера и сетевые события Suricata в одном веб-интерфейсе. Проект предназначен для учебных лабораторий, диагностики и наблюдения за собственной инфраструктурой.

> **Важно:** это инструмент мониторинга, а не межсетевой экран или полноценная SIEM. Он не блокирует соединения и не гарантирует обнаружение каждого сканирования.

---

## Возможности

- Отображение реальных HTTP-запросов к наблюдаемым обработчикам:
  - IP подключившегося узла;
  - HTTP-метод;
  - путь и строка запроса;
  - статус ответа;
  - User-Agent.
- Подключение Suricata через чтение новых записей `eve.json`.
- Отображение событий Suricata типов `alert`, `flow` и `http`.
- Эвристическое предупреждение при высокой частоте HTTP-запросов.
- Фильтрация событий по типу.
- Поиск по загруженным событиям.
- Пауза обновления журнала.
- Экспорт загруженных событий в JSON.
- Доступ к API по токену.
- Адаптивный интерфейс с управлением с клавиатуры.
- Отсутствие внешней аналитики, CDN и сервисов определения IP.

## Как это работает

```text
HTTP-клиент
    │
    ▼
Встроенный сервер aiohttp ── HTTP-события ──┐
                                          │
Сетевой трафик                             ▼
    │                              Буфер событий в памяти
    ▼                                     │
Suricata ── eve.json ── обработчик EVE ─────┘
                                          │
                                          ▼
                                API с токеном доступа
                                          │
                                          ▼
                                 Веб-панель браузера
```

Веб-панель периодически запрашивает новые события через `/api/events`.

Обычный интервал обновления — приблизительно **1,5 секунды**. При наличии накопившихся событий следующая порция запрашивается быстрее.

### HTTP-наблюдение

Встроенный сервер регистрирует запросы к:

- `/probe`;
- другим путям, не занятым служебными обработчиками.

Запросы к `/probe` получают статус `200`. Неизвестные пути — `404`.

Служебные обращения к `/`, `/index.html`, `/api/events` и `/favicon.ico` не попадают во встроенный журнал наблюдения. Это позволяет панели не учитывать собственные запросы обновления как подозрительную активность.

### Сетевое наблюдение

При настройке `SURICATA_EVE` приложение читает новые записи из файла Suricata EVE.

Поддерживаются:

| Тип EVE | Отображение |
|---|---|
| `alert` | Предупреждение с сигнатурой и доступными дополнительными полями |
| `flow` | Информация о сетевом потоке |
| `http` | HTTP-событие, зарегистрированное сетевым сенсором |

При первом подключении существующий файл читается **с конца**: старая история не импортируется.

Обработчик учитывает замену файла при ротации, усечение и неполную последнюю строку. Чтение рассчитано на локальный обычный файл.

## Обнаружение Nmap: что важно знать

**HTTP-сервер не видит произвольные сетевые пакеты.**

Например, SYN-сканирование может не содержать ни одного HTTP-запроса. В этом случае отсутствие записей во встроенном HTTP-журнале — нормальное поведение.

Для наблюдения за таким трафиком нужен сетевой сенсор, например Suricata.

| Действие | Возможный источник событий |
|---|---|
| HTTP-запрос к `/probe` | Встроенный HTTP-журнал |
| Запрос к неизвестному URL | Встроенный HTTP-журнал |
| Определение сервиса с HTTP-пробами | HTTP-журнал, если запросы дошли до обработчика |
| SYN-сканирование без HTTP | Suricata при наличии видимости трафика и соответствующих событий |
| Сканирование других портов | Suricata |
| Трафик вне зоны наблюдения сенсора | Не отображается |

Предупреждения Suricata зависят от включённых правил и конфигурации сенсора. События потоков могут появляться после завершения или тайм-аута потока.

Проект **не определяет название инструмента по каждому соединению**. Упоминание Nmap возможно, если соответствующую сигнатуру сформировала Suricata.

## Быстрый запуск

Скачайте репозиторий или клонируйте его:

```bash
git clone <URL-вашего-репозитория>
cd <каталог-репозитория>
```

### Linux / macOS

Создайте виртуальное окружение:

```bash
python3 -m venv .venv
source .venv/bin/activate
```

Установите зависимости:

```bash
pip install -r requirements.txt
```

Сгенерируйте токен:

```bash
export DASHBOARD_TOKEN="$(python -c 'import secrets; print(secrets.token_urlsafe(32))')"
```

Покажите токен для ввода в панели:

```bash
printf 'Токен панели: %s\n' "$DASHBOARD_TOKEN"
```

Запустите сервер:

```bash
python server.py
```

### Windows PowerShell

Создайте и активируйте виртуальное окружение:

```powershell
py -m venv .venv
.\.venv\Scripts\Activate.ps1
```

Установите зависимости:

```powershell
pip install -r requirements.txt
```

Сгенерируйте токен и запустите сервер:

```powershell
$env:DASHBOARD_TOKEN = python -c "import secrets; print(secrets.token_urlsafe(32))"

Write-Host "Токен панели: $env:DASHBOARD_TOKEN"

python server.py
```

Если политика PowerShell запрещает активацию окружения, можно запускать его Python напрямую:

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements.txt

$env:DASHBOARD_TOKEN = .\.venv\Scripts\python.exe -c "import secrets; print(secrets.token_urlsafe(32))"

Write-Host "Токен панели: $env:DASHBOARD_TOKEN"

.\.venv\Scripts\python.exe server.py
```

### Открытие панели

Перейдите в браузере:

```text
http://127.0.0.1:8080
```

Введите значение `DASHBOARD_TOKEN` и нажмите **«Подключиться»**.

> Не открывайте `index.html` двойным кликом. Страницу должен отдавать Python-сервер.

Для остановки приложения нажмите `Ctrl+C` в терминале сервера.

## Конфигурация

Настройки передаются через переменные окружения.

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `HOST` | `127.0.0.1` | Адрес, на котором слушает сервер |
| `PORT` | `8080` | Порт HTTP-сервера |
| `DASHBOARD_TOKEN` | Не задан | Обязательный токен доступа к API, минимум 24 символа |
| `SURICATA_EVE` | Не задан | Путь к файлу Suricata EVE JSON |

### Изменение порта

Linux / macOS:

```bash
export PORT=8090
python server.py
```

Windows PowerShell:

```powershell
$env:PORT = "8090"
python server.py
```

### Настройки эвристики

Следующие значения заданы константами в `server.py`:

| Константа | Значение | Назначение |
|---|---:|---|
| `HTTP_WINDOW` | `30` | Окно подсчёта HTTP-запросов, секунды |
| `HTTP_THRESHOLD` | `10` | Порог количества запросов |
| `ALERT_COOLDOWN` | `30` | Минимальный интервал между предупреждениями для одного IP |
| `MAX_EVENTS` | `3000` | Размер серверного буфера событий |
| `MAX_SOURCES` | `4096` | Максимальное количество источников в таблице эвристики |

Эвристика создаёт предупреждение при достижении порога запросов от одного наблюдаемого IP.

**Это не доказательство атаки.** Высокую частоту могут создавать легитимные приложения, проверки доступности и пользователи за общим NAT.

Автоматическая блокировка не выполняется.

## Проверка HTTP-журнала

После запуска и подключения панели выполните в другом терминале:

```bash
curl http://127.0.0.1:8080/probe
```

В Windows при необходимости используйте `curl.exe`:

```powershell
curl.exe http://127.0.0.1:8080/probe
```

Ожидаемый результат:

- ответ со статусом `200`;
- новая запись в журнале;
- увеличение счётчика HTTP-запросов.

Проверка неизвестного пути:

```bash
curl http://127.0.0.1:8080/example-missing-page
```

Ожидается статус `404` и соответствующее событие в панели.

### Проверка предупреждения о частоте запросов

Запустите следующий Python-код на своей локальной системе:

```python
from urllib.request import urlopen

for _ in range(10):
    with urlopen("http://127.0.0.1:8080/probe") as response:
        print(response.status)
```

Если запросы выполнятся в пределах 30 секунд, появится предупреждение `HTTP heuristic`.

## Подключение Suricata

### 1. Настройте сенсор

Suricata должна:

- наблюдать нужный сетевой интерфейс;
- видеть проверяемый трафик;
- записывать события в EVE JSON;
- иметь включённые необходимые правила обнаружения.

Пример фрагмента конфигурации EVE:

```yaml
outputs:
  - eve-log:
      enabled: yes
      filetype: regular
      filename: eve.json
      types:
        - alert
        - flow
        - http
```

Это **фрагмент**, а не полный конфигурационный файл Suricata. Согласуйте его с существующими настройками и документацией установленной версии.

### 2. Предоставьте права чтения

Пользователь приложения должен иметь возможность читать файл EVE и проходить по каталогам его пути.

Не запускайте веб-панель от `root` только ради чтения журнала. Используйте минимально необходимые права доступа и учитывайте их сохранение при ротации логов.

### 3. Укажите путь

Linux / macOS:

```bash
export SURICATA_EVE="/var/log/suricata/eve.json"
python server.py
```

Переменная `DASHBOARD_TOKEN` также должна быть задана.

Для проверки наличия файла:

```bash
ls -l /var/log/suricata/eve.json
```

Для просмотра новых записей:

```bash
tail -f /var/log/suricata/eve.json
```

### 4. Проверьте статус

После подключения панели блок **Suricata** покажет состояние чтения файла.

> Статус «файл подключён» означает только доступность EVE. Он не подтверждает правильность захвата трафика и наличие правил обнаружения сканирования.

Если сенсор работает на другой машине, файл EVE не появится на сервере панели автоматически. Необходимо отдельно организовать доставку событий. Встроенного удалённого сборщика в проекте нет.

## Использование интерфейса

### Подключение

Введите токен сервера. В браузере он хранится только в памяти текущей вкладки и отправляется в заголовке `Authorization`.

### Фильтры

Доступны:

- все события;
- HTTP;
- сетевые события;
- предупреждения.

Поиск выполняется по загруженным данным, включая IP, URL, User-Agent и сигнатуры.

### Пауза

Кнопка **«Пауза»** приостанавливает запросы обновления из браузера.

Сервер продолжает собирать события. После возобновления панель получает доступные записи из серверного буфера.

При длительной паузе часть истории может быть вытеснена.

### Экспорт

Кнопка **«Экспорт JSON»** сохраняет события, загруженные в текущую вкладку.

Экспорт не является выгрузкой всего серверного журнала.

## API

### Получение событий

```http
GET /api/events?since=0
Authorization: Bearer <DASHBOARD_TOKEN>
```

Пример:

```bash
curl \
  -H "Authorization: Bearer $DASHBOARD_TOKEN" \
  "http://127.0.0.1:8080/api/events?since=0"
```

Параметр `since` — идентификатор последнего полученного события.

Ответ включает:

- `events` — очередную порцию событий, до 200 записей;
- `cursor` — идентификатор для следующего запроса;
- `latest` — текущий последний идентификатор;
- `truncated` — признак вытеснения части запрошенной истории;
- `server_time` — время сервера;
- `started_at` — время запуска процесса;
- `stats` — счётчики;
- `sensor` — состояние чтения EVE.

Для следующей порции передайте полученный `cursor` в `since`.

### Ответы API

| Статус | Значение |
|---|---|
| `200` | Запрос выполнен |
| `400` | Некорректный параметр `since` |
| `401` | Отсутствующий или неверный токен |

## Хранение данных

Проект не использует базу данных.

- Сервер хранит до **3000 событий** в оперативной памяти.
- Вкладка браузера хранит до **1000 загруженных событий**.
- После перезапуска сервера история и счётчики сбрасываются.
- Старые события EVE при первом подключении не импортируются.
- Экспорт сохраняет только данные текущей вкладки.

Для долговременного хранения нужен отдельный механизм: база данных, сборщик журналов или специализированная система мониторинга.

## Безопасность и приватность

### Доступ к панели

По умолчанию сервер слушает только `127.0.0.1`.

HTML-интерфейс доступен без токена, но получение событий через API требует авторизации.

Не публикуйте токен:

- в репозитории;
- в скриншотах;
- в issue;
- в общедоступных журналах;
- в URL.

### Удалённый доступ

Для удалённой работы используйте HTTPS через настроенный reverse proxy либо SSH-туннель.

Пример туннеля, если приложение работает на удалённом сервере:

```bash
ssh -L 8080:127.0.0.1:8080 user@server
```

После этого откройте локально:

```text
http://127.0.0.1:8080
```

Не передавайте токен через публичное незашифрованное HTTP-соединение.

### Reverse proxy и IP-адреса

Приложение использует IP непосредственного соединения и намеренно не доверяет произвольному `X-Forwarded-For`.

При работе за reverse proxy в HTTP-журнале может отображаться IP прокси.

Поддержку клиентских адресов необходимо настраивать отдельно с явным списком доверенных прокси. Слепое доверие заголовкам клиента позволяет подделывать IP в журнале.

### Содержимое журналов

События могут содержать:

- IP-адреса;
- URL и параметры запросов;
- User-Agent;
- сетевые адреса и порты;
- сигнатуры и категории предупреждений.

В строках запросов могут оказаться секреты, если клиент передаёт их в URL. Учитывайте это перед экспортом и публикацией журналов.

Интерфейс выводит поля событий через `textContent`, а не вставляет их как HTML.

### Ограничения защиты

В текущей версии отсутствуют:

- автоматическая блокировка;
- ограничение частоты запросов на уровне сервера;
- отдельная защита от перебора токена;
- многопользовательская авторизация;
- полноценный аудит доступа;
- долговременное хранение;
- готовая production-конфигурация TLS.

Токен доступа не заменяет сетевую изоляцию и защиту инфраструктуры.

---

## Известные ограничения

1. HTTP-журнал относится только к встроенному Python-серверу, а не ко всем приложениям на машине.
2. Без Suricata приложение не видит чистые TCP/SYN-сканы.
3. Наличие файла EVE не гарантирует обнаружение сканирования.
4. Не все типы событий EVE обрабатываются.
5. HTTP-события встроенного сервера и Suricata могут описывать один и тот же запрос; автоматического объединения нет.
6. User-Agent контролируется клиентом и может быть подделан.
7. IP-адрес не идентифицирует конкретного человека.
8. Поле `duration_ms` встроенного HTTP-события не является полным временем передачи ответа по сети.
9. Чтение EVE рассчитано на локальный файл; сетевые файловые системы могут потребовать отдельного сборщика.
10. Код рассчитан на один процесс приложения: у каждого процесса был бы собственный буфер и собственные счётчики.

## Решение проблем

### Сервер сообщает, что `DASHBOARD_TOKEN` не задан

Создайте переменную окружения с токеном длиной не менее 24 символов.

Linux / macOS:

```bash
export DASHBOARD_TOKEN="$(python -c 'import secrets; print(secrets.token_urlsafe(32))')"
```

Windows PowerShell:

```powershell
$env:DASHBOARD_TOKEN = python -c "import secrets; print(secrets.token_urlsafe(32))"
```

Запускайте сервер из того же терминала.

### Панель сообщает «Неверный токен доступа»

Введите токен, с которым был запущен текущий процесс сервера.

После смены переменной окружения уже работающий процесс не обновляет токен автоматически — сервер нужно перезапустить.

### Ошибка `ModuleNotFoundError: aiohttp`

Установите зависимости в используемое окружение:

```bash
python -m pip install -r requirements.txt
```

### Порт уже занят

Выберите другой порт через `PORT`, затем откройте соответствующий адрес в браузере.

### Запросы панели не появляются в HTTP-журнале

Это предусмотрено: служебные маршруты исключены из наблюдения.

Для проверки используйте:

```bash
curl http://127.0.0.1:8080/probe
```

### Nmap работает, но событий нет

Проверьте:

1. Создаёт ли проверка HTTP-запросы.
2. Подключена ли Suricata.
3. Видит ли она нужный сетевой интерфейс.
4. Появляются ли новые записи непосредственно в EVE.
5. Включены ли подходящие правила.
6. Не ожидается ли завершение или тайм-аут потока.

### Suricata: «нет связи с файлом»

Проверьте:

- значение `SURICATA_EVE`;
- существование файла;
- права чтения;
- права прохода по каталогам;
- настройки ротации.

### Suricata подключена, но старые события отсутствуют

При первом подключении чтение начинается с конца файла. Отображаются только новые записи.

Это ожидаемо: история хранится в оперативной памяти.

### В журнале виден IP прокси

Приложение показывает непосредственного сетевого соседа. Настройте доверенные прокси отдельно, если требуется восстановление клиентского адреса.

## Возможные направления развития

- Долговременное хранение в SQLite или PostgreSQL.
- Интеграция с журналами Nginx и других серверов.
- Отдельный сервис доставки событий Suricata.
- Объединение связанных HTTP- и сетевых событий.
- Настраиваемые правила предупреждений.
- Редактирование или маскирование чувствительных параметров URL.
- Метрики состояния и проверки работоспособности.
- Автоматические тесты API и обработки EVE.
- Production-развёртывание с HTTPS и ограничением доступа.

Эти возможности перечислены как направления развития и не входят в текущую реализацию.

## Ответственное использование

Используйте проект только для собственной инфраструктуры или систем, для которых получено разрешение.

Перед тестированием согласуйте:

- целевые узлы;
- допустимые проверки;
- время проведения;
- интенсивность;
- порядок остановки и уведомления ответственных лиц.

Соблюдайте применимые требования к обработке и хранению журналов.
